# WhisperDoc Technical Release Notes - v3.0.0
**Version Range: v2.25.2 to v3.0.0**

This release marks a major paradigm shift for WhisperDoc, transitioning the system from a pure real-time speech-to-text transcription pipe into an **Intelligent Hybrid AI Dictation & Custom Transformation Engine**. Users can transform transcribed speech using built-in dictation profiles (**Raw**, **Clean Polish**, **Professional**, **Casual Messaging**, and **Technical**) or author and manage custom prompts with Groq's ultra-fast `qwen/qwen3.8-27b` inference (~260ms latency, zero reasoning/CoT tokens) prior to Win32 clipboard injection and auto-paste automation.

---

## Client-Edge LLM Dictation Transformation Subsystem

### Multi-Profile & Custom Prompt Engine
- **Zero-Backend Architectural Independence**: Implemented entirely as a client-side "man-in-the-middle" between transcription completion (`RecordingController._finishRecordingSession`) and the Win32 automation layer (`AutomationService`).
- **Universal Provider Compatibility**: Operates identically whether the client transcribes via the WhisperDoc backend (WebSocket) or Groq Cloud direct transcription.
- **Single API Key & OS Enclave Reuse**: Reuses the Groq API key already stored securely in the Windows Credential Manager enclave (`SecureVaultService`). Zero duplicate key configuration or separate setup required.
- **Polymorphic Profile Architecture**: Core domain models implement the `DictationProfileSpec` abstraction, unifying the five built-in `DictationProfile` presets with dynamic user-defined `CustomProfile` entities.
- **Custom Profile Management & In-Menu Editor**: Supports up to 3 user-defined custom profile slots (`custom1`–`custom3`) with automatic sequential naming, user customization, a 2,000-character prompt safety limit, automatic anti-injection preamble synthesis, and an in-menu modal editor (`ProfileEditorDialog`).
- **Five Dedicated Built-in Profiles**:
  1. **Raw**: Verbatim, unedited transcription without LLM processing.
  2. **Clean Polish**: Removes verbal fillers ("um", "uh", "like", "you know"), false starts, and accidental repetitions while preserving the speaker's exact vocabulary and voice.
  3. **Professional**: Elevates dictation into articulate, executive-grade business prose for emails, reports, and client memos.
  4. **Casual Messaging**: Structures text for natural, conversational team chat (Slack, Discord, SMS) with smooth cadence.
  5. **Technical**: Preserves software engineering terminology, variable casing (`camelCase`, `snake_case`), CLI commands, and wraps code symbols in markdown backticks with zero information loss.

### Fail-Open Latency SLA & Zero-Stalling Pipeline
- **Fail-Open Resilience**: If an LLM transformation exceeds its input-scaled timeout, encounters HTTP 429 rate limiting, returns invalid data, or fails for any reason, the system instantly pastes the raw transcription and surfaces a non-blocking toast. The user is never stalled.
- **Dynamic Input-Scaled Timeouts**: Replaced rigid static timeouts with an adaptive formula:
  $$\text{timeout} = \text{clamp}(1500\text{ ms} + 25\text{ ms} \times \text{wordCount},\; 1500\text{ ms},\; 8000\text{ ms})$$
  Ensures short utterances finish in under 2 seconds while multi-minute dictations receive adequate completion headroom without false-positive timeouts.
- **Lockout State Synchronization**: Extended `RecordingController.isTranscribing` across the entire transformation pipeline in both backend and cloud modes, preventing hotkey race conditions or mid-flight session collisions.
- **Truncation Detection & Guarding**: Added `finishReason` parsing to `GroqChatClient` and hard rejection for `finish_reason == 'length'` in `GroqTransformService` to prevent partial sentence pasting.

### Guard Normalization & Typographic Defense
- **Context-Blind `TransformOutputGuard`**: Sanitizes model responses before they hit the ASCII `TextSanitizer`:
  - Strips any `<think>...</think>` chain-of-thought blocks.
  - Strips enclosing quotes or triple-backtick markdown fences wrapping the response.
  - Converts Unicode typographic punctuation to ASCII equivalents (`‘ ’` $\rightarrow$ `'`, `“ ”` $\rightarrow$ `"`, `– —` $\rightarrow$ `-`, `…` $\rightarrow$ `...`), ensuring contractions like *"don't"* are not mutilated into *"dont"* by ASCII whitelisting.
  - Validates output-to-input length ratios ($0.3 \le \text{ratio} \le 4.5$) to reject hallucinated or truncated responses while accommodating technical markdown expansion.

## UI & Visual Design Polish

- **Interactive Profile Action Button & Dropdown**: Added an interactive, dark-glassmorphic `ProfileActionButton` with dynamic vertical dropdown positioning, slot management, and custom profile creation dialog launcher.
- **Centralized `LockableControl` Architecture**: Implemented a generic `LockableControl` wrapper across `ActionBar`, dimming (0.35 opacity) and blocking pointer events across all 6 secondary controls during active recording sessions while keeping primary recording and silence warning controls responsive.
- **Dynamic Credential & Session Gating**: Automatically disables AI profile selection with an informative tooltip when no Groq key is configured, and disables profile changes during active recording sessions.
- **Context-Aware Transcribing Banner**: Updated `RecordingView` banner to reflect active post-processing ("Polishing (Clean)...") when an AI profile is executing.
- **Incognito Disclosure**: Updated Incognito tooltip to display `"Incognito (Local Only)"` whenever a cloud path is active (Groq transcription or an AI dictation profile), ensuring complete transparency regarding cloud processing boundaries.
