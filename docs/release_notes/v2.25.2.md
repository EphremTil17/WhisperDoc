# WhisperDoc Technical Release Notes - v2.25.2
**Version Range: v2.24.8 to v2.25.2**

This release represents a landmark architectural overhaul of the WhisperDoc Parakeet ASR subsystem, retiring the in-process NVIDIA NeMo/PyTorch toolchain in favor of an isolated, native C++ `parakeet.cpp` (ggml/CUDA) sidecar architecture. This eliminates the severe CPython memory corruption bug documented in `NEMO_CPYTHON_MEMORY_CORRUPTION.md`, purges over 12 GB of runtime dependencies, restores zero-shim Uvicorn protocol execution, introduces a pure-Python silence-aware long-form chunking pipeline, and delivers compiled Windows release distribution binaries.

---

## Architecture: NeMo to Native `parakeet.cpp` Sidecar Migration

### Process-Level Isolation & Memory Safety
- **Out-of-Process Execution**: The Parakeet model now executes inside a dedicated native C++ sidecar container (`parakeet-server`), communicating with the FastAPI application over local HTTP (`/v1/audio/transcriptions` and `/health`).
- **CPython Singleton Memory Corruption Resolved**: By establishing a physical process boundary, we permanently eliminated the native C/CUDA extension conflict that mutated CPython's interned `b" "` singleton (`0x20` -> `0x00`).
- **Zero-Shim Policy Enforced**: Completely removed the in-process `_fixed_ws_upgrade` monkey-patch and `_SAFE_SPACE` h11 workaround in `backend/api_server.py`, returning Uvicorn to standard, unpatched protocol execution.
- **12 GB Toolchain Purged**: Removed `nemo_toolkit[asr]`, PyTorch Lightning, Hydra, Hugging Face transformers, Numba, and Librosa from `backend/pyproject.toml` and `backend/uv.lock`, accelerating image build and container startup times.

### Unified Engine Contract & Health Warmup
- **Consolidated `ParakeetEngine`**: Replaced the 450+ line NeMo implementation with a lightweight HTTP client implementing the `BaseEngine` interface.
- **Lazy CUDA Graph Priming**: Implemented an automated 10-second silent audio warmup decode during startup to pre-initialize ggml CUDA execution graphs and eliminate first-request latency spikes.
- **Re-entrant Synchronization**: Protected client state transitions with re-entrant locking (`RLock`) to prevent deadlocks during health checks and warmups.

## Audio Pipeline: Silence-Aware Long-Form Chunking

### Pure-Python RMS Pause Detection
- **`backend/engine/silence_chunker.py`**: Added a zero-dependency audio chunking pipeline that computes RMS energy across 20ms frames without requiring heavy external VAD dependencies (like Silero or WebRTC VAD).
- **Acoustic Boundary Planning**: Dynamically searches for natural silence dips within a 24s to 30s window. If no pause is found, it falls back to a bounded cut with 0.5s acoustic overlap padding to prevent phoneme clipping.

### Word-Level Timestamp Alignment & Deduplication
- **Midpoint Timestamp Filtering**: Long recordings are submitted to the sidecar with `timestamp_granularities[]="word"`. The engine evaluates each word's midpoint timestamp against logical non-overlapping sample boundaries, seamlessly deduplicating overlap speech without word omissions or repetitions.
- **Demonstrated Throughput**: Transcribed the 516.85-second TED Talk audio corpus in 4.044 seconds engine time (128x real-time factor) across 20 bounded requests with 19 quiet cuts and zero boundary damage.
- **Fast-Path Preservation**: Short utterances (<= 30s) continue using the fast-path single-request evaluation.

## Tooling, Logging & Infrastructure

### CUDA Graph Diagnostic Filtering
- **`backend/tools/parakeet_log_filter.sh`**: Added a POSIX stream filter to strip repetitive, benign ggml CUDA graph messages (`ggml_cuda_graph_compute: graph is not updated`, `cudaGraphExecUpdate failed`) from container stdout while preserving genuine errors and operational logs.
- **Docker Compose Integration**: Wrapped the `parakeet-server` container command to pipe stdout/stderr through the filter.

### Version Bumper Hardening
- **Cross-Platform CRLF/LF Handling**: Hardened `scripts/bump_version.py` with `_read_text_preserving_newlines()` and `_write_text_preserving_newlines()` (`newline=""`) and updated regex pattern anchors from `$` to `[^\r\n]*`.
- **Multi-Rule Caching**: Introduced an in-memory batching dictionary to accumulate multiple replacements targeting the same file before writing to disk.
- **Strict Error Enforcement**: Configured explicit `RuntimeError` failure when `uv` is unavailable during lockfile synchronization.
