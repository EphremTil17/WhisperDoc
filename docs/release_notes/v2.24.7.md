# WhisperDoc Technical Release Notes - v2.24.7
**Version Range: v2.24.6 to v2.24.7**

This release focuses on hardening the client-side audio input availability subsystem and making hardware status states more reliable. By transitioning away from a lossy binary boolean state (`hasAudioInput`), we eliminate invalid representations of hardware status (such as collapsing permission denied, missing device, unplugged device, and uninitialized states into one bit) that historically led to dead UI states and unexpected crashes.

Additionally, this version introduces an adaptive monitoring mechanism that polls for hardware recovery when the app is in a degraded state, and links Flutter lifecycle observers directly to UI orchestration rather than low-level context-blind services.

## Audio Availability Subsystem Hardening

### Rich Status & Sealed Exceptions
- Introduced `AudioInputStatus` enum (`unknown`, `available`, `noDevice`, `selectedUnavailable`, `permissionDenied`) along with extensions defining `canRecord` and `bannerMessage` helpers.
- Replaced untyped catcher overrides in the controller with a clean sealed hierarchy of typed hardware exceptions (`NoAudioDeviceException`, `MicPermissionDeniedException`).

### Context-Blind Services & UI Lifecycle
- Decoupled `AudioService` from Flutter widgets and context-aware overrides.
- Implemented `WidgetsBindingObserver` at the `HomeScreen` boundary to trigger passive re-checks when the app resumes focus, keeping Flutter bindings out of lower service directories.

### Adaptive Recovery Monitor
- Added an adaptive self-recovering monitor in `AudioService` that polls every 3 seconds ONLY during degraded/unavailable hardware states and halts automatically once status resolves to `available`.

## Test & Verification Coverage
- Created robust mock test configurations inside `audio_service_test.dart` using `fakeAsync` to verify recovery timers, exceptions, and lifecycle status changes.
- Updated `recording_controller_test.dart` to cover the new typed status transitions.
